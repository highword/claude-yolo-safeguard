    **Step 1: Create src/pipeline/types.ts** with these exact types:

    ```typescript
    import type { Rule, RuleMatch } from "../types/rule";

    /** Re-export shell-quote's parse entry type for internal use */
    export type ParseEntry =
      | string
      | { op: string }
      | { op: "glob"; pattern: string }
      | { comment: string };

    /** A single segment from a compound command, split at operators */
    export interface Segment {
      tokens: ParseEntry[];
      original: string; // rebuilt string from tokens
    }

    /** Character span mapping a token to its position in the rebuilt string */
    export interface TokenSpan {
      token: ParseEntry;
      start: number;
      end: number;
      position: "command" | "argument" | "flag";
      isMultiWord: boolean; // true if token contains spaces (was quoted)
    }

    /** Pre-compiled rule for matching performance */
    export interface CompiledRule {
      rule: Rule;
      regex: RegExp;
    }

    /** Frame in the recursive analysis stack */
    export interface AnalysisFrame {
      command: string;
      depth: number;
      source: "root" | "shell-wrapper" | "subshell" | "interpreter";
    }

    /** Result from the full analysis pipeline */
    export interface AnalysisResult {
      matches: RuleMatch[];
      segmentCount: number;
      maxDepth: number;
    }
    ```

    **Step 2: Create tests/pipeline/parser.test.ts** with RED tests for all behaviors listed above.

    **Step 3: Create src/pipeline/parser.ts** implementing:
    - `parseCommand(cmd: string): ParseEntry[]` — wraps shell-quote's `parse()` with no env argument (per D-44, POSIX only)
    - `splitSegments(tokens: ParseEntry[]): Segment[]` — splits at operator tokens where op is one of: "&&", "||", ";", "|", "&". Does NOT split at "<", ">", ">>", ">&", "<(", "(", ")". Each segment gets its `original` field set via `rebuildSegment`.
    - `rebuildSegment(tokens: ParseEntry[]): string` — joins tokens with spaces. String tokens are used directly. Glob tokens use their `pattern` field. Operator tokens (redirections that stayed in segment) use their `op` field. Comment tokens are ignored.
    - `buildTokenSpans(tokens: ParseEntry[]): TokenSpan[]` — for each string token in the segment, calculates character offset (start/end) in the rebuilt string and classifies position:
      - Index 0 in the segment = "command"
      - Token starts with "-" = "flag"
      - Everything else = "argument"
      - `isMultiWord` = token contains at least one space character

    Per D-29: Use `import { parse } from "shell-quote"`.
    Per D-30: Split at &&, ||, ;, |, & operators only.
    Per D-34: Quoted strings become single tokens automatically via shell-quote — no extra handling needed.
