    ```typescript
    import type { RuleMatch } from "../types/rule";
    import type { CompiledRule } from "../pipeline/types";
    import { compileRules } from "../pipeline/matcher";
    import { CONTENT_RULES } from "./rules";
    import { isHighEntropySecret } from "./entropy";

    const COMPILED_CONTENT_RULES: CompiledRule[] = compileRules(CONTENT_RULES);
    const MAX_CONTENT_SIZE = 500 * 1024; // 500KB fail-open threshold
    const IGNORE_MARKER = "// safeguard-ignore-next-line";

    // Path patterns for test/doc/fixture detection (case-insensitive matching)
    const TEST_DOC_PATTERNS = ["test", "spec", "__tests__", "fixture", "mock", ".md", "example"];

    export interface ScanResult {
      matches: RuleMatch[];
      skipped: boolean;
    }

    export function scanContent(content: string, filePath?: string): ScanResult { ... }
    ```

    Implementation details:
    1. **Size guard:** If `content.length > MAX_CONTENT_SIZE`, return `{ matches: [], skipped: true }`.
    2. **Keyword quick-reject:** Build a content-specific keyword set from `CONTENT_RULES`. Lowercase the content, check if ANY keyword is present. If none found, return `{ matches: [], skipped: false }`.
    3. **Per-line scanning:** Split content by `\n`. Iterate with `skipNext` boolean flag. If line contains `IGNORE_MARKER` (exact, case-sensitive `line.includes(IGNORE_MARKER)`), set `skipNext = true` and continue. If `skipNext` is true, reset it to false and continue (skip this line).
    4. **Per-line matching:** For each non-skipped line, check if line contains any keyword (lowercase comparison). If yes, test each compiled rule's regex against the line. For matches, push to results.
    5. **Entropy validation for secrets:** For matches where `rule.id === "content.hardcoded-secret"`, extract the captured group (the token value between quotes). If the regex used `exec()`, group 1 is the token. Run `isHighEntropySecret(group1)`. If false, filter out the match. If no captured group is available, keep the match (fail-open).
    6. **Path-based severity adjustment:** If `filePath` is provided and `isTestOrDocPath(filePath)` returns true, iterate matches. For each match where `rule.severity !== "CRITICAL"`, create a shallow copy: `match.rule = { ...match.rule, severity: "MEDIUM" }`. CRITICAL is never downgraded.
    7. `isTestOrDocPath(filePath: string): boolean` — lowercase the filePath, check if any TEST_DOC_PATTERNS string is contained.

    IMPORTANT: When mutating match severity, ALWAYS spread the rule object (`{ ...match.rule, severity: "MEDIUM" }`). Never mutate the shared compiled rule reference.

    Run `bun test tests/content/ignore-marker.test.ts tests/content/path-adjustment.test.ts` — must PASS.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03 | Denial of Service | scanContent regex loop | mitigate | 500KB size limit enforced at entry; keyword quick-reject eliminates most content before regex; per-line scanning bounds regex input size; performance tests verify <20ms for 200KB |
| T-05-04 | Elevation of Privilege | isTestOrDocPath severity downgrade | mitigate | CRITICAL severity never downgraded regardless of path; only HIGH->MEDIUM transition allowed; attacker cannot use path to bypass secret detection |
| T-05-05 | Tampering | ignore marker bypass | accept | Attacker who can insert `// safeguard-ignore-next-line` already has write access to the file; the marker is a developer convenience, not a security boundary |
</threat_model>
